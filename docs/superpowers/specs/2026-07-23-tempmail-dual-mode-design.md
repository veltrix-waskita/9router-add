# Temp-mail dual mode for grok-cli + kiro

**Date:** 2026-07-23  
**Status:** Approved for implementation planning  
**Scope:** Email source dual-mode (`imap` | `tempmail`) for `grok-cli` and `kiro` email registration.  
**References:** [x-farm](https://github.com/feb-frmn/x-farm) (`mail_tm.py` / `EmailBox`), [GAC](https://github.com/wanglinsaputra/GAC) (`@wanglinsaputra/tempmail-wrapper`).

## Problem

Today both email-method providers depend on a user-owned domain + Cloudflare Email Routing catch-all into Gmail IMAP:

- Auto-credentials require `providers.<name>.aliasDomain`.
- OTP is read only via IMAP (`src/services/imap-otp.js` in Node / `read_otp` in Python worker).
- That works, but needs domain + IMAP secrets for every machine and is slower to stand up than pure temp-mail.

GAC and x-farm already farm xAI with temp-mail (proven: **ncaori**, **zoromail**). We want the same option without removing the IMAP path.

## Goals

1. Dual mode per run: **IMAP/alias** or **temp-mail**, selectable in the interactive runner (and passable via options/CLI later).
2. Hybrid stack:
   - **Node:** `@wanglinsaputra/tempmail-wrapper` for kiro + shared service.
   - **Python:** port of x-farm `EmailBox` subset inside grok-cli worker for pure-HTTP OTP.
3. Default providers: `ncaori,zoromail` (round-robin create + fallback on create failure).
4. Auto-credentials work **without** `aliasDomain` when email source is temp-mail.
5. IMAP path remains fully functional and is still the default when the user picks it (or when temp-mail is not configured and source is forced to imap).

## Non-goals

- Google OAuth for grok-cli.
- Replacing captcha / Turnstile handling.
- Supporting all 16 wrapper providers as first-class tested paths (config may list them; only ncaori+zoromail are “supported” in docs/tests).
- Live temp-mail calls in unit tests / CI.
- Changing remote-mode auth or 9router poll/device-code contracts.

## Architecture

```
config.tempmail.providers = ["ncaori", "zoromail"]   // default
runner → email source: imap | tempmail

┌─ IMAP mode (existing) ──────────────────────────────────────┐
│ credentials.email from aliasDomain / manual / batch JSON    │
│ OTP: Gmail IMAP (Node kiro / Python grok-cli worker)        │
│ requires config.imap.user + config.imap.password            │
└─────────────────────────────────────────────────────────────┘

┌─ TEMPMAIL mode (new) ───────────────────────────────────────┐
│ credentials.email generated by temp-mail (or pre-set)       │
│ OTP: HTTP poll — no IMAP required                           │
│  kiro     → src/services/tempmail.js (npm wrapper)          │
│  grok-cli → worker/tempmail.py (EmailBox port)              │
└─────────────────────────────────────────────────────────────┘
```

**Decision:** Approach A — shared Node service + dual OTP backends (Node package for kiro, Python EmailBox for grok worker). Rejected Node-only OTP injection into the worker (couples mid-flight timing) and Python-only for kiro (spawn cost, loses GAC wrapper).

## Config

```json
{
  "tempmail": {
    "providers": ["ncaori", "zoromail"],
    "timeoutMs": 120000,
    "intervalMs": 3000
  },
  "imap": { "...": "unchanged" },
  "providers": {
    "grok-cli": { "aliasDomain": "minom.my.id" },
    "kiro": { "aliasDomain": "minom.my.id" }
  }
}
```

| Key | Default | Notes |
|-----|---------|--------|
| `tempmail.providers` | `["ncaori","zoromail"]` | Order = prefer list for create fallback |
| `tempmail.timeoutMs` | `120000` | OTP wait budget |
| `tempmail.intervalMs` | `3000` | Poll interval (Node); Python may use ~3s sleep |

Env override (optional, runner/CLI): `TEMPMAIL_PROVIDER=ncaori,zoromail` (same semantics as GAC).

`options.emailSource`: `"imap"` | `"tempmail"`. Set by runner; providers read it from `options` (not from global config alone, so batch can stay mixed later if needed).

## Components

### 1. `src/services/tempmail.js` (new, Node)

Responsibilities:

- `normalizeProviders(listOrString)` → string[].
- `createMailbox({ providers, blockedDomains? })` → `{ email, provider, client }`.
  - Round-robin start index (module-level counter, same idea as GAC `mailProviderIdx`).
  - On create failure or blocked domain, try next provider; if all fail, throw aggregated error.
- `waitForOtp(client, email, { timeoutMs, intervalMs, extract? })` → OTP string.
  - Prefer subject/preview extract before full body read (GAC `peekCode` pattern).
- `extractTempmailOtp(text)` — shared xAI-aware extractor:
  - labeled `code: ABC-DEF` / `ABC-DEF` bare with context
  - labeled 6-char alnum
  - labeled 6-digit (AWS/kiro-friendly)
  - skip ad markers / known non-OTP hyphen tokens (port filters from x-farm `_extract_code`)
- `isBlockedDomain(domain)` — static set: yopmail, mailto.plus, tempmail.plus, guerrillamail*, mailinator, 10minutemail, temp-mail.org, throwaway.email, sharklasers.com.

Dependency: `@wanglinsaputra/tempmail-wrapper` (ESM). Load via dynamic `import()` from CJS so existing CommonJS tree stays intact.

Security: never log OTP or provider session tokens; logging email + provider name is OK.

### 2. `src/providers/grok-cli/worker/tempmail.py` (new, Python)

Port from x-farm `mail_tm.py` **subset only**:

- `_extract_code` (+ skip/ad/xAI markers)
- `NcaoriMail`
- `Zoromail`
- `EmailBox` with `DEFAULT_PREFER = ["ncaori","zoromail"]` (full prefer list may remain as code comments / ALL for future, but default prefer is the two proven ones)

Interface:

- `EmailBox(prefer=None).create_account() -> str`
- `EmailBox.wait_code(timeout=150) -> str`
- `provider_name`, `address`

Uses `curl_cffi` session (already a worker dep). No new Python package required beyond existing worker requirements.

### 3. grok-cli worker (`signup.py`) integration

- Env:
  - `GROK_EMAIL_SOURCE=imap|tempmail` (default `imap` for backward compatibility)
  - `GROK_TEMPMAIL_PROVIDERS=ncaori,zoromail`
  - When `tempmail`: IMAP env vars optional; when `imap`: current IMAP required.
- Flow:
  1. If source is tempmail and `GROK_EMAIL` empty → `box.create_account()`, set email, emit step event `{step:"tempmail_create", provider, email}`.
  2. If source is tempmail and `GROK_EMAIL` already set → still construct mailbox client for that provider path only if API allows inbox-by-address; **otherwise** always create-and-use (preferred: always create in worker for tempmail so token/session stays local). Spec choice: **worker always owns create+wait in tempmail mode**; Node may pre-generate email only for display/ledger by creating in Node then passing email is **not** required for grok — keep OTP entirely in Python to avoid dual clients.
  3. After `CreateEmailValidationCode`, call `box.wait_code()` instead of `read_otp`.
- Node `buildWorkerEnv`: map `options.emailSource` and `config.tempmail.providers`; omit IMAP password requirement when tempmail.
- Node `add()`: if `emailSource === 'tempmail'`, do **not** throw on missing IMAP; still require password (and email only if not auto-generated — see credentials).

**Auto + tempmail for grok-cli:** runner generates password + name; leaves email empty or placeholder; worker creates mailbox and returns final email via JSONL event so Node can rename connection correctly.

JSONL additions:

- `{"event":"step","step":"tempmail_create","status":"ok","provider":"ncaori","email":"..."}` (email in event is OK; do not include OTP)
- `{"event":"step","step":"otp","status":"ok","source":"tempmail","elapsed_s":N}` (no code field)

On success result, include `email` when worker-created: `{"kind":"result","ok":true,"email":"..."}` so Node renames with real address.

### 4. kiro email-mode integration

In `automateEmailLogin` (or immediately before OTP wait):

- If `options.emailSource === 'tempmail'`:
  1. `createMailbox` via `services.tempmail`.
  2. Use returned email as the registration alias (override credentials.email for the flow).
  3. Fill browser email field with that address.
  4. Wait OTP with `waitForOtp` instead of `imap.getOtpViaImap`.
  5. Return resolved email for rename.
- If imap: unchanged path; still require IMAP config.

Kiro Google method (`@gmail.com`) ignores emailSource.

### 5. Credentials service

Extend `generateAccounts` (or add `generateAccountsForSource`):

| source | email | password/name | requires |
|--------|-------|---------------|----------|
| imap | aliasDomain aliases | random | `aliasDomain` + IMAP at run time |
| tempmail | **omit / null** for grok (worker creates); **create via Node tempmail** for kiro batch prebuild optional | random | `tempmail.providers` |

Recommended behavior:

- **kiro auto + tempmail:** Node `createMailbox` per account up front (email known before browser); store provider name on `options.tempmailProvider` and keep client only during that account’s run (do not serialize client). Simpler alternative: create mailbox at start of each `add()` inside provider — preferred to avoid stale inboxes between batch queue and run. Spec: **create mailbox inside provider `add()` / email flow**, not in credentials prebuild. Credentials auto only fills password + name; email may be placeholder `tempmail@pending.local` replaced at run, or empty with provider accepting missing email when source=tempmail.

Final rule:

- Auto + tempmail → `{ credentials: { password, name }, options: { emailSource: 'tempmail' } }` (email filled during add).
- Auto + imap → existing alias emails.
- Save file still mode 0600; after success, runner/provider should persist resolved email when available (append to generated file or log only — **minimum:** log resolved email; optional update save file out of scope unless easy).

### 6. Runner

New step after provider + exec mode, **before** proxy (only if provider is `grok-cli` or `kiro`):

```
Email source:
  1) IMAP / aliasDomain   — existing CF catch-all + Gmail IMAP
  2) temp-mail            — ncaori,zoromail (HTTP OTP, no IMAP)
```

- Apply `options.emailSource` to every account in the plan.
- Auto path:
  - imap → existing `generateAccounts` (aliasDomain required).
  - tempmail → generate password/name only; no aliasDomain.
- Preflight:
  - imap → check IMAP config present.
  - tempmail → check providers non-empty; do not require IMAP.
- Display: show source + provider list; never print IMAP password.

Antigravity: no email-source step (Google only).

### 7. package.json

Add dependency:

```json
"@wanglinsaputra/tempmail-wrapper": "^1.2.0"
```

## Error handling

| Failure | Behavior |
|---------|----------|
| All tempmail create providers fail | Throw; account fails; batch continues to next |
| OTP timeout | Throw with source label (`tempmail` / `imap`) and elapsed |
| Blocked domain returned by provider | Skip provider, try next |
| tempmail mode but empty providers | Preflight error in runner; provider throws clear message |
| imap mode missing IMAP | Existing error messages |
| kiro Google + tempmail selected | Ignore tempmail; use Google path |
| Worker tempmail create fails | JSONL result ok:false step tempmail_create; Node fails account |

No silent fallback from tempmail → imap within a single account (user chose dual mode explicitly per run). Cross-mode fallback was rejected in product choice.

## Security

- Never log/print: OTP, IMAP password, machine-id, cli-secret, device_code, codeVerifier, temp-mail API tokens/cookies.
- Device secrets stay in Node (unchanged).
- Generated accounts files mode `0600`, gitignored.
- Proxy display remains host:port only.
- Remote dashboard password still HTTPS-only (unchanged).

## Risks

- **xAI domain blocklist changes** — ncaori/zoromail may break; mitigate by config-driven provider list and clear create errors.
- **ESM/CJS interop** for tempmail-wrapper — use dynamic import; pin version ^1.2.0.
- **kiro AWS** may reject ncaori domains more aggressively than xAI — document; IMAP remains available.
- **Worker-created email vs Node rename** — must thread `email` through JSONL result (specified above).
